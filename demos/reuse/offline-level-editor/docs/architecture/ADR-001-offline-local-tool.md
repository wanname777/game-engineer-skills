# ADR-001 — 离线关卡工具的运行与数据路线

状态：建议，尚未采用到新工程、尚未验证。日期：2026-11-13。
来源：raw-input.md；参考仓库 package.json、package-lock.json、设计保存与下载源码（精确路径与证据边界见 reference/current-repository-evidence.md）。

## 背景与硬约束

交付是创作工具，附最小预览；单人两周；桌面优先；运行必须可断外网；不接账号、云服务或排行榜；文件共享即可。预算上限、用户地区、全OS支持和首次安装是否必须完全离线尚未给定，不反复追问已给条件。

需要分别回答：本机能打开；朋友设备能打开同版本工具；数据刷新/重启恢复；跨设备的数据靠文件携带。这四件事各自验收。

## 三种可实施方案

| 方案 | 满足硬约束的方式 | 维护与构建 | 费用/地区/权限 | 数据与分享 | 迁移代价 |
| --- | --- | --- | --- | --- | --- |
| A：静态网页、React/TS/Vite、Node本机服务 | 所有JS/CSS/地块随包、本机不调用远端；网格渲染和简单试走足够 | 单个前端工程；Node内置服务器无需生产npm依赖；能借鉴当前仓库状态/JSON校验方法 | 无托管/账号费项；开发下载npm与浏览器需核验地区可达；费用上限未知；浏览器文件选择无需额外密钥 | localStorage固定origin恢复；Blob文件导出与File API导入；朋友需要本机运行环境 | 可把领域模型移到桌面壳；存储/文件适配器可替换 |
| B：Tauri 2桌面壳 + 网页UI | 打包资源后原生离线运行；浏览器刷新对应窗口重开恢复 | 增加Rust、OS构建工具链、打包与原生权限；单人两周发行矩阵成本较高 | 无云服务要求；OS工具链与签名/公证费用、地区下载尚未查证，不能预填免费 | 原生文件对话框和应用目录数据；朋友需要匹配OS构建 | 可以复用网页领域模型；后续封装较直接 |
| C：Godot 4工具工程 + 2D运行场景 | 自带2D渲染与输入；离线导出桌面程序 | 编辑器面板、序列化、持久化、预览场景都需建立；复杂玩法增长时收益明显 | 无云服务要求；版本、模板下载与系统分发费用/许可需拥有源核验 | user://保存与JSON文件；朋友需要匹配OS导出 | 网页模型/UI复用少；复杂物理时可重新评估 |

三项通过“能以本地资源离线运行”的硬约束。依赖在线托管或云数据库作为核心路径的变体不符合约束。候选没有声称当前设备已经构建成功或有既定OS支持。

## 推荐与理由

建议A。两周的主要风险是建立编辑/预览/文件往返/恢复闭环，不是复杂2D运行时。静态网页的输入、状态、有限网格及JSON能力足够；不引入远端存储或完整引擎。现有仓库已有React网页、状态快照验证与Blob下载方法，提供可读借鉴来源；它尚不是新工具实现。

B保留为用户明确要求“一键安装、无需Node”后的升级路线；此时必须核验每个支持OS的打包、签名、文件权限和重启恢复。C在预览扩展为平台跳跃、复杂碰撞/物理或大型关卡游戏时重新评估。当前没有证据证明使用完整游戏引擎能在两周降低创作工具成本。

## 建议架构与单一来源

- UI：React + TypeScript；单一编辑器根类限定局部样式；共享颜色/间距位于未来工程 src/styles.css。
- 数据：纯TypeScript LevelV1、validator、serialize/parse、放置规则。编辑画面、预览快照、本机保存、导入/导出使用同一领域模型。
- 渲染：首版用语义DOM网格/简单绘制，最多4096格；不加渲染库。预览采用相同地块样式/坐标规则，临时运行态只有角色位置与结果，不能写入LevelV1。
- 适配器：LocalStorageRepository（浏览器缓存）、JsonFileAdapter（文件）、LocalServerLauncher（离线资源服务）。领域模型不直接调用localStorage或DOM文件操作。
- 依赖：建议采用当前可借鉴主版本React19/TS5.9/Vite7，不把参考锁文件当成新工程已安装版本。创建工程时读取锁文件、Node与构建日志后记录实际版本。

参考锁文件读取时的版本见 current-repository-evidence.md；当前参考工程的构建工具依赖不必整体复制，例如视频依赖不是此工具必需。

## 运行、离线分发与地址

未来工程约定开发命令 npm ci、npm run dev，行为检查 npm run check（构建+领域单测+真实浏览器）。这些命令尚待T-001建立。开发环境需Node22.12+或24+。

离线用户包计划包含 dist/、launch.mjs、启动说明及示例关卡。launch.mjs用Node内置HTTP/文件功能只绑定127.0.0.1:4186，静态服务dist目录；拒绝目录穿越并提供正确MIME。用户装有Node后运行 node launch.mjs，浏览器打开固定地址。打包后的运行不能调用npm registry/CDN/远端字体，也不能要求 npm ci。首个启动器以当前macOS桌面为验证目标；其他OS启动方式待实测。

端口被占用必须清楚报错退出，不能自动换端口。host或端口改变就是不同origin，localStorage不会自动迁移；UI与说明必须提示用JSON导入迁移。开发模式也使用固定origin，但验收不能复用旧网页缓存掩盖离线资源缺失。

“完全没有第一次联网”的安装条件没有被指定。首版保证准备好离线运行包与运行环境后断外网冷启动；首次安装Node/开发依赖可能需要网络或用户已准备好的安装介质。若要求朋友无需Node或真正首次完全离线安装，复议A/B和分发预算。

## JSON格式、保存与导入规则

规范建议：

| 字段 | 规则 |
| --- | --- |
| format | 固定字符串 youzao.level |
| schemaVersion | 固定整数1；其他版本拒绝并说明不兼容 |
| name | 去首尾空白后1到80字符 |
| width、height | 1到64整数；总格数最多4096 |
| tiles | 一维row-major整数数组，长度严格 width×height；0为空/阻挡、1地面可走、2墙阻挡 |
| spawn、goal | null或精确的{x,y}整数坐标，位于地图内且对应地面；两者非null时必须不同 |

只序列化上述字段；不把UI选中工具、视口、运行角色、时间戳或本机路径混入关卡。未知顶层/坐标字段拒绝，避免静默丢掉未来版本语义。256KiB输入限制在 file.text() 之前检查；解析为unknown再验证，整份成功后一次性替换编辑状态。文件只承载数据，不解析脚本/HTML/远端资源引用。

存储键建议 youzao.level-editor.saved.v1；保存写入规范JSON成功后才能消除dirty。刷新读取同一个validator；空键开始新关卡，损坏键提示恢复失败且不自动覆盖。保存失败保留dirty及编辑数据，并允许JSON导出。导入只更新未保存编辑状态，不改恢复点；保存是显式提交恢复点。浏览器清除数据、隐私模式或另一浏览器会失去本机缓存，文件备份由使用者负责。

数据可有效但尚不能预览：spawn/goal为null允许保存/导出；点击预览时要求两者有效且不同。 preview snapshot = clone(LevelV1)，运行态不修改此对象；返回编辑结构相同。初版不强制自动证明终点可达。

## 验证切片与验收状态

T-001先在目标设备离线启动骨架且端口策略正确；T-002/T-003/T-005执行地块→保存→刷新→导出→独立会话导入→再保存/刷新。T-004加入同模型预览并验证运行不污染编辑数据。T-007从清缓存的独立浏览器环境、断外网、重启本机服务执行全路径。T-008执行第二设备文件交换；同机器独立会话只证明存储隔离，不宣称第二设备通过。

当前状态：上述技术验证均未执行。只有原始条件、源码阅读和恢复脚本输出是真实已发生证据。

## 后果、责任与复议

维护者负责锁文件、离线包一致性、JSON兼容说明与实际设备验收；使用者负责导出重要关卡备份。首版只支持v1，遇到未来版本拒绝并引导同版本工具；添加v2前需要旧fixture迁移测试。

若需要超过4096格、更多资产、多关卡、自动保存/历史、可靠大数据存储，复议IndexedDB及渲染方式。若需要账号或同步，用户范围与权限/备份/地区决策都需重新建立。首次离线安装、免Node安装或支持多个OS的明确要求触发桌面壳/分发复议。
