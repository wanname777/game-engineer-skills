# 月面温室 · 界面方案

玩家的目标是在十轮内，让月球温室中的所有植株获得光照。核心动作是布置三种种植格；每轮只能移动一个种植格。

以上是本次提供的玩法事实。以下界面结构为设计建议，当前 HTML 交付的是介绍页；游戏场景交互尚未实现。

## 介绍页

| 区域 | 层级与意图 | 原文 / 输入 | 动作与反馈 |
| --- | --- | --- | --- |
| 标题区 | 深绿底、米白标题，暖黄入口；原创温室与三种叶形仅作装饰 | 项目名「月面温室」 | 「阅读玩法」滚到原文并把键盘焦点移到章节标题 |
| 玩法 | 最主要阅读区，正文 18–21px | 完整保留玩法原文 | 静态阅读与复制 |
| 游戏模式 | 与玩法并列的事实区 | 离线单人，尚未实现联网和排行榜。 | 静态阅读，无联网或排行榜入口 |
| 植物标签 | 暖黄标签块，深绿文字 | `<script>alert('seed')</script>` | 原样阅读、复制，HTML 转义后显示 |
| 交付工具 | 页脚，与玩法文本分开 | 实际 tokens.json 与 interface-spec.json | 两个链接可真实下载文件，键盘与触控可用 |

手机使用单列、24px 侧边距和至少 44px 的链接命中高度。1440px 使用 1184px 的内容上限：标题与装饰双列，玩法左列，模式与标签右列。所有原文保留阅读顺序。没有外部字体、图片、跟踪请求或自动动画。

## 游戏界面建议

建议顶部显示轮数上限和当前回合移动状态；中央显示种植格；桌面右侧、窄屏下方显示选中种植格与光照反馈。选中对象使用边框加文字，光照使用图标加文字，避免只依赖颜色。

选择种植格与移动分为两步：选择只改变界面焦点；移动到合法目标才更新场景，并把本轮移动标识设为已使用。这是交互建议，具体移动距离、合法位置和回合推进方式尚未给定。一次合法移动后，本回合进一步移动应禁用，并显示原因。

所有场景、属性和回合反馈读取同一份结构化状态。对象使用稳定 id、种类、标签、坐标、尺寸和可见状态；选中对象的详情跟随同一 id。数据校验应拒绝重复 id、未知类型、非有限数值和越界坐标。无关卡数据应显示「尚无关卡」，无植株时不能以空列表判定为胜利。

光照来源、遮挡、判定时机和是否要求同时获得光照没有给定。界面不编造植物种类名称、地图尺寸、关卡数量或成功比例。终局反馈以实际规则函数为准，十轮耗尽后的结果判定顺序与文案待规则确定。

介绍页无加载、保存或本地存档行为，因此这些状态标为不适用。若后续确认存档需求，再增加独立深拷贝快照、schema 版本和错误反馈；读取、解析或写入失败时保留当前场景，并提供下载输出。当前不承诺刷新恢复游戏进度。

## 品牌变量与状态

深绿 `#163d2c` 是主文字与标题区背景；米白 `#f5f1e7` 是页面阅读底色，浅米白 `#fffcf4` 是卡片；暖黄 `#e9bf4d` 用于入口、标签与装饰光斑。暖黄填充上使用深绿文字。正文、卡片、辅助文字、标题区与按钮的计算对比分别为 10.71、11.79、6.33、10.71、6.92，均达到普通文字 4.5:1。

默认、选中、禁用、加载、无数据、错误和存储失败状态均在 interface-spec.json 按区域标注。结构化文件同时区分已实现的介绍页区域与仅提供方案的游戏区域，避免把设计方案描述成可玩功能。
