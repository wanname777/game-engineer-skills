# 制作游戏发布短片

先读项目 README.md、docs/project/brief.md；仅加载本 skill。读 [来源与证据](references/sources.md) 保持归因准确，实施前读 [渲染契约](references/render-contract.md)。

## 输入与输出

从用户或 brief 提取游戏名、目标观众、时长、画幅、情绪、关键物件、交付位置。缺少次要项时用 [brief 模板](assets/motion-brief.json) 的默认值继续，并标出假设；关键素材权限不明时使用原创几何图形与合成声音。

交付三幕分镜、三张风格帧、交互预览、至少 1280×720 / 30 fps / H.264 / AAC 的 MP4、封面、contact sheet、含指标与来源哈希的 JSON。不要把预览页或截图称为视频成片。

## 工作流

1. **写 brief**：用一句话说明情绪与行动；选一个贯穿物件，让三个空间由运动、视线或构图承接。写每幕时段、主动作与声音事件。控制字量，让画面承担叙事。
2. **先画三张风格帧**：选择开场、转折、片尾的时间点，统一配色、笔画、角色比例与字号。默认不等待二次确认；用户要求审批时交付可检查的静帧。
3. **实现单一时间源**：将画面与声音写成纯函数 `f(t)`。从绝对秒数计算缓动、路径、透明度和音符包络；禁止渲染函数依赖累计状态、随机数或当前墙钟。让同一物件在幕间位置连续。
4. **接预览**：提供播放/暂停、拖动、逐帧、速度、静帧跳转、音量开关。只在用户操作后启动声音。提供 `window.render(t)`、`window.READY`、`window.DUR`；等待字体与素材后再标记 READY。rAF 仅驱动外部播放时钟。
5. **导出真实视频**：运行 `npm run render:motion`，或 `node .agents/skills/create-motion-showreel/scripts/export-showreel.mjs --project <项目路径>`。脚本通过 Playwright 调用同一画面函数，对 `i/fps` 逐帧截取，合成同一时间轴 PCM，再由 FFmpeg 编码。`--quick` 仅供 480p 迭代，最终必须再运行默认 720p。
6. **验证再交付**：运行 `npm run check` 和 `npm run render:motion`。检查开场、中段、片尾；观看 MP4 与 contact sheet，实际听音后才声称完成听感检查。验证重复乱序 seek 的像素哈希、无黑帧、实际时长/帧率/帧数、无削波与可闻音量。只报告已生成且检查过的成果。

## 失败处理

- 未安装依赖：使用 Node ≥22.12、`npm ci`；渲染脚本会在内存中编译原始 TS 时间源，不要求 Node 的实验类型剥离开关。
- 缺 Chromium：运行 `npx playwright install chromium`；本机已有浏览器时显式设置 `MOTION_BROWSER_PATH`，不要伪造截图结果。
- READY 超时：检查字体、素材加载和页面错误；先修复再导出。
- 像素不一致：排查随机数、每帧累加、未完成加载与隐藏的 CSS 动画，回到纯时间函数。
- FFmpeg 或指标失败：保留错误信息，修复后重跑；不要发布半成品，也不要提前声称 CI、渲染或部署成功。
- 外部素材缺失：使用原创图形与本地合成音轨；不要求 API 密钥，不下载或提交视频原件、字幕或个人信息。

## 验收

确认三个空间有承接、关键物件连续、文字在 720p 可读、任意拖动可确定性重现、声音与动作同时间轴、成片为真正 MP4。确认 JSON 包含编码与验证指标，记录来源证据等级，并在 THIRD_PARTY_NOTICES.md 写明借鉴的方法而非冒称作品授权。
