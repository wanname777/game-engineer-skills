# 澄清项目

1. 先读项目 `README.md`、`AGENTS.md`、brief和decisions。遵守项目现有路径；无约定时用 `docs/project/brief.md`、`docs/project/decisions.md`。把已有答案列为事实，不重新索取。
2. 用一句话收拢「谁在什么场景，完成什么动作，获得什么结果」。区分交付本身（工具、网页、skill）与工具里的示例游戏。禁止把示例的试玩目标代替项目本身验收。
3. 从缺口中选最多三个会改变实施方向的问题：第一位用户/玩家、最短完整路径、可观察成功标准、第一版不做范围、运行平台、时间与素材预算。每次只问未知且高价值项；最多两轮，用户已给出授权和答案时直接执行。
4. 不阻塞可独立开展的工作。未回答项标记「假设」或「待定」，写明代价与需要验证的时机；禁止虚构预算、日期、访谈、用户人数或测试结果。
5. 参照 [产物模板](assets/brief-template.md) 生成可编辑PRD；参照 [决策模板](assets/decisions-template.md) 记录结论、理由、来源、状态和复议条件。验收写成可执行步骤和可观察结果，计划与已执行证据分开。
6. 给出本轮一个可交付的小切片、未解决依赖与下一步。下一阶段只加载一个相关skill，保留已确认决策，避免重新采访。

按需读 [访谈规则](references/interview.md)；讨论迁移来源时读 [来源](references/sources.md)。输出文件使用UTF-8和真实换行；不默认持久化联系方式、密钥或私人访谈原文。
