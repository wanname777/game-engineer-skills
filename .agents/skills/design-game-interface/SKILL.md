# 游戏界面设计

## 输入与边界

- 先读项目 `README.md`、`docs/project/brief.md`，确认玩法、受众、平台、状态及技术约束。
- 收集玩法原文、必需界面、品牌变量、目标设备和原始参考链接。缺少阻塞输入时先实现可逆骨架，再一次性询问缺项；不要编造玩法或来源。
- 用 [输入模板](assets/design-input.template.json) 标注内容来源、组件意图、交互、空态和错误态。作品参考只提取方法；作者归属与证据等级读 [来源](references/sources.md)。

## 操作

1. **先叙事。** 用一句话说明玩家目标，列出核心动作与状态变化；把玩法原文与界面解释分别保存。介绍页保留原文，不混入操作提示、宣传承诺或未给定功能。
2. **再结构。** 为每个区域标注层级、内容来源、输入、动作、反馈。设计主操作、选中、禁用、加载、存储失败与无数据状态；删掉无法执行的按钮。
3. **统一变量。** 用一套颜色、字体、间距、圆角驱动界面和场景。沿用项目已有变量源；本项目共享变量在 `src/tokens.css`（由 `src/styles.css` 加载），局部变体限定 feature 根类。先检查文字对比，再设计主题切换。
4. **确定性实现。** 用结构化场景状态生成 SVG、Canvas 或组件。对象选择、移动、主题、版本必须操作同一份状态；存储数据先校验，捕获读取、解析、写入失败并提供可见反馈。参考 [工作流](references/workflow.md) 的具体契约。
5. **导出内容。** 对本项目的介绍页用 `python3 .agents/skills/design-game-interface/scripts/export_design.py --input demos/design/gameplay.md --tokens demos/design/tokens.json --output /tmp/starport-introduction.html`。输入只支持标题和纯文本段落；其余 Markdown 原样显示，HTML 全部转义。运行前先校验完整输入，失败不得输出伪成功。
6. **实际验收。** 本地启动；桌面和手机实际打开，检查排版、文本、对象操作、触控、键盘焦点、主题和下载。修改行为后运行 `npm run check`，记录真实退出状态。截图和源码只能证明各自内容，不等同完整观看参考视频。

## 输出

- 可运行界面与结构化状态；有意义的行为检查；当前来源与证据等级。
- 共享变量 JSON、玩法原文和忠实介绍页；导出不引入外部跟踪、素材或凭据。
- 报告已执行的验证、失败项与限制；禁止预报构建、CI、发布成功。

## 验收与失败处理

- 核心操作产生可见反馈；选中对象与属性一致；隐藏对象可再次选中；移动和尺寸有边界。
- 两个主题以上同步更新场景、界面和导出；移动端没有横向溢出，表单和按钮可触控，焦点可见；尊重减少动态效果偏好。
- 保存快照独立于后续编辑；坏 JSON、旧 schema、重复对象、存储禁用或配额不足不导致页面崩溃；错误时保留页面设计并提供可下载输出。
- 介绍页逐段与原文核对；未知 Markdown 不擅自解释；`<script>` 等输入作为文字显示。输入为空、变量缺失或无效时说明具体原因并停止该导出。
- 浏览器或渲染工具不可用时报告「未完成视觉验收」；不要用类型检查替代实际视觉结论。
