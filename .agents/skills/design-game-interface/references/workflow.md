# 可验证的界面契约

## 结构化标注

从原始文档填写 `assets/design-input.template.json`。每个区域至少包含 `purpose`、`source`、`controls`、`states`；玩法内容与解释组件分开。标注可以改，源文档保持可追踪。

先以最小操作闭环做首屏：选择对象 → 改一个属性 → 场景变化 → 保存 → 载入。优先让这个闭环完整，再增加主题和导出。

## 场景状态

- 对象拥有稳定 id、可读名称、种类、坐标、尺寸和显示状态。
- 渲染与属性面板读取同一对象；隐藏只影响显示，不能使对象永远不可访问。
- 键盘和范围滑杆调用同一状态更新函数；坐标和缩放有边界。
- 排序、遮挡、hit area 与选中提示属于确定性渲染；截图只能证明采样时刻。

## 版本与存储

- 快照深复制，不持有会被编辑的引用。
- 给存储键添加 schema 版本，限制版本数量与文档大小；校验枚举、有限数字、唯一对象 id。
- `getItem`、`JSON.parse`、`setItem` 都可能失败。读取失败不阻塞编辑；只有写入成功后显示「已保存」。
- 载入时同步主题、场景、对象、文档；清空之前生成的介绍页，避免源文变了但导出过时。

## 忠实页面

脚本输入：UTF-8 玩法 Markdown 与含 `colors` 的变量 JSON。支持一个首级标题作为页名、标题作为章节，非空行作为原文段落；列表、链接、强调符号保留为文字。不自动添加卖点、发行日期、玩法承诺、作者评价或故事背景。

对所有标题和段落做 HTML 转义；CSS 颜色只接受十六进制。展示性说明放页脚，不混入玩法。逐段对照源文检查遗漏、重排和新增。浏览器预览与下载应采用同一份输入快照。

## 实际验证

在桌面和 390px 手机宽度实际打开，验证无溢出、触控命中、可读层级；只用键盘完成选择、移动、切换面板和保存。保存后刷新与载入；模拟坏 JSON 和写入失败。生成包含中文、`<>&` 与未知 Markdown 的页面，检查文字是否忠实且不可执行。

检查重点是用户可观察的结果，而不是重复实现细节。把执行命令、结果与限制交给发布记录，不在产品操作流展示内部工具名。
